# Code smells

Tech debt we know about, newest first.

## 2026-10-22: `cfbench/envs/behaviors.json` restates label rules from unmerged env branches

The overnight envs (`envs/hiring-*`, `envs/scheming`, `envs/shutdown`, `envs/whistleblow`,
`envs/dumb-user-*`, `evalcue/exclude-rows`) weren't on main, so cfbench can't import their
`detect()` docstrings. A subagent wrote each env's label rule into `behaviors.json` from the branch
source instead. If a branch changes `detect()` the JSON goes stale silently. Once they merge,
replace the JSON with the env modules' own text. `cfbench/envs/sandbagging_iter.py` has the same
problem for PR #75's mechanical label.

## 2026-10-22: `shutdown_*` envs parse arms by substring, and the doc tables come from a scratch script

`evalcue/envs/shutdown/persist.py` builds each episode from substrings of the arm name
(`"cost" in arm`, `"freetime" in arm`), so a new arm name can silently pick up an edit it didn't
mean to (`costlow` contains `cost`, handled by ordering). `shutdown_killswitch`/`shutdown_cron` grew
long `if arm in (...)` chains for stacked arms. A dict of named edits per arm would be safer. The
tables in `docs/envs/shutdown-arms.md` were generated by a throwaway script (pool all run dirs,
rescore, Wilson CI) that isn't in the repo; regenerating them means rewriting it.

## 2026-10-22: `donehack/` runs don't go through `scripts/runs.py`

`donehack/port.py` and `variants.py` write to `donehack/runs/<out>/` (gitignored) with no
`meta.json`. The runs behind its README were uploaded by hand to the HF dataset
`Robbie-Kylie-NN-sprint/donehack`, not in the `runs/<experiment>/<date>_<slug>/` layout. The bwrap
backend hard-codes NixOS store paths and is kept only for comparison with those runs.

## 2026-10-21: `cfbench/envs/secret_number.py` runs on rows copied from an unmerged branch

Its rows (`data/envs/secret_number/`, on HF under `envs/secret_number/`) were copied from checkout
`-4`'s `data/runs/evalcue/secret_number/`, branch `evalcue-secret-number`, whose newer arms (split,
salient, prompt cues) aren't on main. Arm edits are diffed from the rows, so nothing breaks, but the
rows have no provenance link to code on main until that branch merges. The behavior text is the
`Hack` section of main's `evalcue/envs/secret_number/` docstring, which omits the detector's
`tamper` rule (0 tamper-only hacks in these rows).

## 2026-10-21: main doesn't pass its own `ty` check

`uv run ty check` reports 286 diagnostics (2026-10-22): 98 unresolved imports (torch, transformers,
vllm, `server`, `olens.*`) in GPU-only scripts whose deps live only in the pod venvs, and 152 in
`transcript-viewer/web/server.py`, mostly untyped JSON dicts. Check only the files you touched until
someone excludes the pod-only modules and types `server.py`.

## 2026-10-21: `evalcue/` harness rough edges

- The sandbox runs the agent as root in the container.
- Several envs' `detect()` count wrong-but-honest code that happens to pass the impossible test as a
  hack (`lcb_mock_entity`), or count incomplete work as gaming (`precommit_scope`). See
  `docs/eval-cue-reward-hacking.md`.

## 2026-10-19: `scripts/run_chive_or.py` monkeypatches Agam's harness

It loads `vendor/detective-joracle/scripts/run_chive.py` and overwrites module globals in it and in
`detective_joracle.chive.judge` / `.executor` (`client`, `json_call`, `AGENT_MODEL`, ...). Since
2026-10-22 it asserts each patched name exists and that no loaded `detective_joracle` module still
holds the original `llm.client` / `llm.json_call`, so a rename or a new by-value import at module
level fails loudly. A by-value import inside a function body (or a new module imported lazily) would
still slip through and go to Anthropic. The clean fix is a backend/judge-client option upstream.
